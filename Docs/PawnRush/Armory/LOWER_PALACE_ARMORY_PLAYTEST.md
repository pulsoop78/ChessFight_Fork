# 아랫궁 무구실 · 회색 프리팹 플레이 검증

2026-11-26. 새4종 약도를 저장된 회색 블록아웃과 오프라인 테스트 씬으로 구현했다. **Unity Editor는 이 클라우드에 없어 실제 입력·물리 완주·4~5분 통과 시간은 아직 확인하지 못했다.**

## 바로 실행

- 씬: `Assets/Scenes/LowerPalaceArmoryTrial.unity`
- 프리팹: `Assets/Prefabs/Obstacles/LowerPalaceArmoryTrial.prefab`
- 메뉴: **ChessFight → Prototype → Armory → Open Grayscale Trial**
- 씬을 열고 Play. 기존 `RagdollPawn`과 기존 `RagdollTuning`을 사용한다. 구조물은 저장된 프리팹이며 실행 중 새로 생성하지 않는다. 테스트 캐릭터·구간 이름 표시와 필요 시 카메라만 실행 시 만든다.

프리팹을 별도 씬에 놓아 시험할 수도 있다. `ArmoryCourseTrial`은 오프라인 테스트 드라이버이므로 다른 게임의 플레이어/카메라 드라이버와 함께 켜지 않는다. 실제 게임 구간으로 통합할 때는 이 드라이버를 끄고 기존 스폰/진행 시스템에 `CourseModule`과 장치를 연결하는 작업이 필요하다. 로비·Steam·멀티플레이는 연결하지 않았다.

| 조작 | 동작 |

12명을 띄워 잡기·방패·동시 복귀를 시험할 수 있지만, 선택하지 않은 캐릭터는 **자동으로 코스를 풀지 않는다**. 자동 봇이나 네트워크 참가자로 구현한 것이 아니다. 정지 중에도 Rigidbody의 일반 물리는 계속되므로 물리 전체를 멈추는 메뉴가 아니다.

## 저장된 구조

[새4종 약도](LOWER_PALACE_ARMORY_MINIMAP.png)의342m 중심선/12m 폭, 두 고정 경사로, 높이0→3→6m, S/C1~C4/도착 안전 단과4단 하강 출구를 저장했다. 낙하 시 약1.5초 뒤 구간 직전에서 복귀한다. C4는 주동선이 플랫폼 가장자리를 지나므로 실제 접근을 감지하도록 체크포인트 범위를 깊이±3.4m로 잡았다. 높은 벽·진열대·갑옷·엄폐물에는 `NoClimbSurface`를 붙여 외곽 우회를 제한했다.

구조물 재질은 `ArmoryTrialGray`, `ArmoryTrialDarkGray`, `ArmoryTrialLightGray` 세 무채색이다. 전용 씬 배경/환경광도 회색이다. 창 예고·타격 범위·감시 시선은 색상 없이 밝기/점멸로 구별한다. 캐릭터 외형과 기존 팀 표시는 별개이며 공유 재질을 바꾸지 않았다.

창 위치는 **매 파동, 각 가로줄마다 독립적으로** 추첨한다. 3개80%/2개20%를 뽑은 뒤4칸 전체를 섞어 해당 수만큼 올린다. 앞줄의 안전 칸을 다음 줄에 복사하거나, 첫 줄의 안전 칸을 정해진 순서로 이동시키거나, 꺾이는 연결 칸을 강제로 남기지 않는다. 각 행에1~2개 안전 칸은 남지만 전 구간을 일자로 통과할 수 있는 길은 보장하지 않는다. 무작위이므로 우연히 같은 줄/위치가 나올 수는 있다. 새 배치는 기존처럼 휴식 시작에 정해지고2초 예고를 거쳐 상승하며 예고 중 재추첨하지 않는다.

창 피격은 기존 IHitReceiver의 넘어짐(래그돌) 처리로 연결하며 추가 속도는0이다. 뒤/위로 날리는 두 설정은 ArmorySpearFloor와 저장 프리팹에서 제거했다. Stun Seconds 기본0.6초(최소0.1초)로 쓰러져 있는 시간을 조절한다. 이동 중이던 관성이나 다른 캐릭터가 가한 힘을 지우는 기능은 아니며 창 자체가 발사력을 추가하지 않는다.

`ArmoryPawnIntent`는 실제 이동량과 입력 방향을 함께 보고, 입력 없음·벽에 막힘·수직 흔들림·피격 후1.2초·기절/래그돌/잡힘/공중을 제외한다. 일반 외력과 자발적 이동이 정확히 같은 방향으로 섞이는 모든 상황을 분해하는 물리 해석기는 아니므로, 사람끼리 계속 비비거나 동시에 입력하며 밀리는 경우의 감시 판정은 별도 수동 확인 대상이다.

방패 대여 상한은 기본35초로, 누군가 사격 구역 안에서 방패를 계속 잡고 있어도 보급을 영구 봉쇄하지 못하게 한다. 회수 시 기존 `PawnHand`의 disabled collider 해제 경로를 사용하며 물리 콜백에서 관절을 즉시 파괴하거나 잡힌 물체를 순간이동하지 않는다. 방패는 양면 모두 일반 충돌체로 화살을 막는다. 방향/틈은 실제 면적에 따른다.

## 자동 확인과 실제 확인의 구분

- `python3 Tools/RoyalPalace/build_armory_trial.py --check`: 새 프리팹/씬/무채색 재질이 생성 원본과 일치하는지 확인한다. 다시 생성하려면 `--overwrite`지만 **Unity에서 수동 편집한 새 프리팹의 값이 덮이므로 저장본을 먼저 보존**한다.
- 자산 검사: 모든 참조, 단일 프리팹 인스턴스,4종 바인딩,24창/2듀라한/3방패/9석궁/27화살,6개CP, 경사로의11.8m 폭/65단계 높이 연결,4단 계단,3개 무채색 재질/조명.
- 실제 C# 컨트롤러를 stand-in으로 실행: 10,000창 파동 안전 경로·예고/피격/쿨다운, 듀라한 각도/도끼 거리/타격, 화살 경계/가림/3방향 무작위 선택·연속 반복·예고 일치·정면 사격 차단/장착·회전·내려놓기·비활성화·방패 회수, 감시 시선/엄폐/초기화, 캐릭터 의도 판정31조건.
- Linux Roslyn 외부 런타임 컴파일은 Unity 참조 DLL로 타입/API 연결을 검사한다. 실제 Unity Editor/PhysX 실행 검증이 아니다.

Unity에서 확인할 순서:

1. 씬 Play 후1번에서 창 예고 가독성·피격·안전길·R 복귀를 확인한다.
2. 숫자2에서 플랫폼을 바라보는 듀라한의 머리 없는 목/다리 갑주 실루엣을 확인한다. 철퇴의 좁은 범위와 도끼 부채꼴의 착지 순간을 피한 뒤, 무기가 바닥에 머무는 동안 즉시 가로질러도 피격/충돌로 막히지 않는지 확인한다.
3. 숫자3으로 방패 보급 앞에 이동한다. 방패에 접근해 E로 들고 마우스로 좌/우/정면 석궁을 바라보며 차단한다. 옆·뒤를 노출하면 피격되는지, E 내려놓기·R 복귀·F3 초기화·대여 만료 시 충돌/보급 복구도 확인한다.
4. 4번에서 시선 안 정지/전진, 진열대 엄폐, 상대에게 밀리거나 잡힌 상태의 감시 제외를 확인한다.
5. Tab으로 캐릭터를 바꾸고 C4 자동 기록·낙하1.5초 복구·F3 초기화·Esc 시계 정지, 출구까지 연속 주행을 확인한다.
6. 실제12인/멀티플레이 성능 및 평균4~5분 통과 시간은 이 오프라인 테스트 결과와 구분해서 측정한다.


## 난도 조정 · 2026-11-16

창은 4칸 가로줄마다2~3개를 상승시킨다. 11/26부터 각 행이 독립 무작위 배치이며 연결 칸을 강제로 남기지 않는다. F3는 새 씨앗으로 전체 패턴 순서를 초기화한다.

듀라한은 기존6초 주기에서3.5초(휴식0.8+준비1.1+타격0.25+유지0.55+회수0.8)로 변경했다. 두 무기는1.75초 위상 차이를 둔다.

석궁은 좌/우/정면3개씩 총9개다(정면은 진행 방향 앞 Z=129m에서 뒤쪽으로 발사). 2.8초마다 좌/우/정면 중 한 방향의3개를 무작위로 선택하며(같은 방향 연속 허용), 각 사격의 예고가 시작될 때 해당 구역의 가장 가까운 플레이어 쪽 조준선을 고정한다. 1초 조준선 예고 뒤 화살은 고정된 방향으로 직진하며 추적하지 않는다. 발사 구역/체크포인트 경계는 유지한다. 선택은 판의 씨앗과 사격 번호로 정하므로 예고 중 방향이 바뀌거나 프레임 수에 따라 다시 추첨되지 않는다. F3로 새 판을 시작하면 씨앗이 바뀌어 사격 순서도 달라진다.

방패는 2.8×3×0.25m→1.8×2.1×0.2m로 축소했다. 3m 이내의 비어 있는 방패를 E로 들고 다시 E로 내려놓는다. 장착 중에는 골반 앞0.9m에 수직으로 유지하며 마우스의 수평 시점 방향을 따른다. 방패 면이 화살을 가로막으면 차단되고 옆·뒤·면적 밖에서는 피격된다. 장착 중 방패는 kinematic이며 소유 캐릭터와의 충돌만 제외하고 일반 화살/환경 충돌체는 유지한다. 내려놓기·R 복귀·낙하·초기화·비활성화·대여 회수 때 장착/충돌 제외를 해제한다. 기존 우클릭 물리 잡기는 별도로 남는다.

감시 갑옷은(92,140)/(112,149)로 간격을 늘렸다. 정면 감시2초→0.8초에180°뒤돌기→뒤돌아3.8초 유지→0.8초 정면 복귀→바닥 예고 점멸1.2초 순서다. 복귀/예고 중에는 발각시키지 않고, 예고 뒤 감시 단계에서만 기존 자발적 이동 조건을 검사한다. 회색 시선 발판은 방향·거리/구역에 맞춰 저장했다. 사용자 실제 조작감/난도 확인은 대기다.


## 듀라한 방향/실루엣과 착지 후 통과 · 2026-11-22

왼쪽 듀라한은+X(플랫폼) 방향, 오른쪽은-X 방향으로 갑옷 외형을 회전했다. 공격 구역/무기 회전축은 기존 위치에 유지해 타격 방향과 범위가 돌아가지 않게 했다. 약8.7m 높이의 머리 없는 갑옷에 열린 목 테두리, 가슴판/문장, 어깨, 상완/팔꿈치/전완/장갑, 허벅지/무릎/정강이/장화를 추가했다. 감시 구간의 갑옷 모델은 별도로 유지한다. 기존 왼쪽 대검 모형은 철퇴 손잡이/둥근 머리/돌기 판으로 교체했고 오른쪽 도끼는 유지한다. 세 회색 재질만 사용한다.

무기는 기존처럼 고체 충돌체 없이 보이며, 착지한 첫 물리 프레임에만 구역 내 캐릭터당1회 타격한다. 해당 순간에 아무도 없어도 타격은 소진되므로 다음 프레임부터 들어온 캐릭터를 뒤늦게 때리지 않는다. Hold Seconds는 무기가 내려가 있는 연출 시간이며 지속 피해 시간이 아니다. 바닥은 착지0.08초만 짧게 밝아지고, 무기가 내려가 있는 나머지 시간에는 어두워진다. 새 주기/새 씨앗/시계 되감기에는 다음 타격을 다시 준비한다.

자동 확인은 플랫폼 방향/갑주 부품/무기 고체 충돌체 없음과 착지 후 진입·빈 타격 후 진입·도끼/철퇴의 타격 소진을 포함한다. 실제 Unity 카메라에서 실루엣/완주/통과 감각은 미확인이다.


## 창 패턴 변경 · 2026-11-23

한 판 내내 고정이었던 세로 안전줄을 제거했다. 자동 검사10,000개 파동에서 연속 패턴 차이, 첫 안전 칸의 한 칸 이동, 행별2~3개 상승, 안전 칸 비상승, 행 사이 상하좌우 연결, 같은 씨앗/파동 재현을 확인한다. 씬/프리팹 수치와 예고·상승·휴식 시간은 유지한다. Unity 실제 회피/동시 주행은 미확인이다.
